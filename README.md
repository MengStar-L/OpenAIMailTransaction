# 拾光 · Atelier

[GitHub 仓库](https://github.com/MengStar-L/OpenAIMailTransaction) · [下载 Release](https://github.com/MengStar-L/OpenAIMailTransaction/releases) · [安装与更新说明](docs/INSTALL.md)

Linux（systemd，amd64 / arm64）默认安装到 `/opt/shiguang`：

```bash
curl -fL https://github.com/MengStar-L/OpenAIMailTransaction/releases/latest/download/install.sh -o install.sh
sudo bash install.sh
```

Go 编写的临时接码兑换站。管理员生成并分发 CDK，用户兑换 SMSBower 的 OpenAI 手机号或邮箱资源，查看验证码并完成订单。采用奶白与浅雾蓝的简约二次元界面，包含猫咪插画、本地托管的站酷快乐体、细节动效、手机适配，以及可选的 HTTPS 图片或视频背景。

前端直接嵌入 Go 程序；SQLite 保存订单与 CDK，无需 Node.js 或独立数据库。系统不包含在线收款、自动售卡支付或用户注册功能。

## 本地启动

在项目根目录打开 PowerShell。首次配置时复制示例文件；已有 `.env` 时保留原文件。

```powershell
Copy-Item .env.example .env
```

保持 `APP_MODE=demo`，运行已构建的 Windows 程序：

```powershell
.\bin\atelier.exe
```

也可双击项目根目录的 `start.cmd`；它会先切换到项目目录，确保读取正确的 `.env` 和数据目录。

或安装 Go 1.27 后从源码启动：

```powershell
go run .
```

打开 [兑换页](http://127.0.0.1:8080/) 或 [管理后台](http://127.0.0.1:8080/admin)。首次访问后台会显示“设置管理员”：输入并确认 12–128 个字符的密码，首个成功提交的人即成为管理员。设置成功后直接进入后台，初始化入口永久关闭，后续通过密码登录。密码仅保存加盐哈希到 SQLite，不在配置文件中设置，也不会打印到日志。

多个浏览器同时提交时只有一个能够完成初始化。升级已有数据目录时，原 `admin.json` 中的密码哈希会迁移至数据库，保留原管理员身份；新数据目录不生成该文件。

演示码为 `DEMO-PHONE`、`DEMO-EMAIL`。兑换后约 15 秒出现模拟验证码，不会购买真实资源。演示码也遵循实际配额规则：每个资源首次收到验证码才计 1 次，未收码且确认释放后可继续获取；同一邮箱最多接收 3 封。刷新页面或重启程序不会重置已用额度。需要继续体验时，在后台生成新 CDK。

## 连接真实资源

停止演示程序，在 `.env` 设置以下参数后重新启动。真实模式必须使用独立的数据目录，不能复用 `data/demo`。

```dotenv
APP_MODE=live
LISTEN_ADDR=0.0.0.0:8080
DATA_DIR=data/live
SMSBOWER_API_BASE=https://smsbower.page
COOKIE_SECURE=false
TRUSTED_PROXIES=
```

程序从启动时的当前目录读取 `.env`；已有系统环境变量优先。运行模式、监听地址等环境配置修改后需要重启。管理员密码由首次后台初始化设置，不读取 `ADMIN_PASSWORD` 环境变量。

正式模式可以先启动，再登录后台，在“设置 → 服务连接”填写 SMSBower API 密钥并保存；保存后立即生效，无需重启。未配置密钥时禁止发行新 CDK 和购买资源，不会回退到演示资源。密钥输入框始终不回显已保存内容，留空保存会保留原密钥；需要替换时输入新密钥。存在进行中或待核查订单时不能替换已有密钥，应先完成或核对这些订单；尚无密钥时仍可补填，以恢复订单处理。“已配置”表示密钥已保存，上游账号有效性和资源可用性以实际请求结果为准。

API 密钥通过 AES-GCM 加密后保存在 SQLite 的独立元数据中，加密密钥由数据目录的 `secret.key` 派生。设置接口、公开配置及 CDK 快照均不返回或包含 API 密钥。升级旧版本时，仅在数据库尚无密钥的情况下导入原 `SMSBOWER_API_KEY` 环境配置；已有数据库密钥优先，后续统一通过后台设置管理。

登录 `/admin`，先在“设置”完成资源配置，再生成 CDK：

| 设置 | 要求 |
| --- | --- |
| API 密钥 | 在服务连接中填写，保存后立即生效；留空保留已保存密钥 |
| 手机号服务 / 邮箱服务 | 默认均为 `dr`，已分别核对官方 OpenAI 服务表 |
| 手机号国家 | 手填一个或多个官方国家编号（逗号分隔），从 API 搜索多选，或选择全部（`*`）；不是国际区号 |
| 手机号 / 邮箱价格上限 | 分别填写大于 0 的金额；单位沿用上游 API，程序不换算货币 |
| 邮箱域名 | 默认 `gmail.com`，可改为上游实际支持的域名 |
| 本地等待时间 | 邮箱默认 25 分钟，手机号默认 20 分钟；属于本地接码等待上限，不代表上游有效期 |
| 背景 | 默认奶白色；可选择图片或视频，并填写可直接访问的 HTTPS 地址 |

生成时保存资源配置快照。手机号的国家范围和价格上限使用后台当前设置，保存后立即约束所有 CDK 的渠道查询和新购买，已发行的 CDK 同样生效；用户页面每 10 秒及返回页面时刷新可选渠道。服务、域名及等待时间仍按 CDK 原配置，已领取资源继续接码；暂停某类资源兑换立即生效。每批可生成 1–200 枚，可设置有效期、1–1000 个有效邮箱或号码及备注。“已用 / 额度”统计成功资源数，不统计购买尝试。例如额度为 3，可获得 3 个收到有效验证码的邮箱；每个邮箱还可接收后续邮件，最多 3 封，不额外扣 CDK 额度。管理员可在 CDK 列表查看、复制完整码。完整码在数据库中加密保存，兑换校验仍使用哈希；公开接口不返回完整码。CSV 使用需要管理员登录的随机下载链接，导出内容仅在服务器内存保留 10 分钟，程序重启后即失效；兑换码不会放入下载地址。

手机号设置会预览所选国家内、价格不超过上限且有库存的全部渠道，支持搜索和分页。用户输入手机号 CDK 后先查询渠道，再选择国家与渠道领取；管理员“接码”页也可直接选择渠道。查询不占用额度、不购买资源。购买前重新查询并验证 CDK 的国家及价格范围，通过 `providerIds` 锁定所选渠道。库存仅作参考；所选渠道明确返回无号时，在 10 秒内继续尝试，期间不更换渠道或提高价格。仍无号时暂时隐藏该渠道，10 分钟后恢复展示资格，届时仍按上游库存和价格筛选。超时等购买结果不明的情况先核对订单，不自动重复购买。

渠道等级名为「星芽」（Bronze）、「月辉」（Silver）、「日冕」（Gold）。[官方 API](https://smsbower.app/api/?page=client) 的完整渠道报价目前只返回价格、数量和渠道编号；前十国家接口可确认部分 Gold 渠道。程序只映射有依据的等级，缺失时显示「未评级」，不根据价格推测等级。所有原生下拉框均以统一的浅色菜单增强，保留键盘操作和表单校验。

## 临时资源如何处理

同一 CDK 会恢复已有订单，刷新不会重复购买。每个邮箱或号码首次收到上游返回的有效验证码时扣 1 个额度，重复查询和同邮箱后续接码不会重复扣除。

未收码的资源可直接点击取消，只有上游确认释放后才能重新获取。购买次数不占用成功额度，未收码取消后可反复重取，不再受原来的“最多尝试次数”限制。手机号仍受上游购买后 2 分钟的释放限制；提前点击会立即保存取消请求，由后台自动等待并确认释放，关闭页面或重启服务后继续处理。取消期间会查询验证码，防止收码与取消竞态。已经收到验证码的资源不能退回成功额度。复制手机号时自动去掉开头的 `+`，邮箱和验证码保持原样。

同一邮箱最多接收 3 封有效验证码。收到前两封后，后台会自动准备下一封，无需点击，关闭页面仍会继续；第三封收到后保留完成按钮，不请求第四封。后续接码通过上游邮箱 `setStatus` 的 `status=5` 请求，3 封是本平台的本地上限，不保证上游所有邮箱和服务均支持全部轮次。页面保留各封验证码及复制按钮。即使 CDK 额度已全部用完，当前邮箱仍可在期限内接收剩余轮次。

上游明确拒绝续收时，每轮最多自动尝试 3 次、间隔 30 秒，次数与等待时间在重启后保留。页面显示“正在准备下一封”或“稍后自动重试”；自动尝试结束后提供“重试接收”，也可以结束邮箱。结果不明时只查询核对，不自动重发续收请求。

不再需要当前邮箱时点击“结束邮箱”。等待第 2 或第 3 封期间也可结束，已扣的成功额度不返还。上游确认结束后，仍有 CDK 额度时可点击“获取下一个”；取消后则点击“重新获取”，均无需再次输入 CDK。未确认释放或完成前不会购买下一个资源。

页面倒计时是本地等待上限，不保证上游一定在该时刻到期。明确的上游到期时间会缩短本地期限。后台持续查询活动订单，即使用户关闭页面，也会处理过期取消和已收码完成；这些工作依赖服务进程持续运行。服务重启后继续处理保存的订单。

邮箱从排队变为成功分配后，页面会播放一次柔和提示音，并在浏览器标签标题显示“【邮箱已就绪】”。右上角铃铛可分别关闭声音与标签提醒，设置保存在当前浏览器并同步同站点标签页。返回聚焦页面后清除标签提示；正在查看页面时提示约 8 秒。同一订单轮询、刷新和后续验证码不会重复触发到达提醒。管理员切到其他后台页面后，已恢复的邮箱排队仍可提醒。

提示音受浏览器自动播放限制，首次点击或键盘操作会尝试启用；恢复页面后还未启用时，可点铃铛内的“启用声音”。后台标签页继续检查邮箱分配，但浏览器休眠、节能限流或关闭页面会延后或停止前端提醒；服务端订单处理不受此开关影响。提醒无需桌面通知权限，也不向外发送邮箱地址或验证码。

如果购买请求超时、响应损坏，或者购买途中程序中断，上游可能已经扣费。系统会保留待核查订单，不会自动重复购买。请求下一封的结果不明时，显示“接码状态待确认”，继续查询但不会重发下一封请求；结束请求尚未确认时，显示“完成确认中”，阻止新资源购买。邮箱结束待确认时先通过只读状态接口核对，确认上游已完成便同步结束，不重复发送结束请求。完成确认从首次结束意图起最多自动重试约 2 分钟（重启不重置）；仍无法确认或明确拒绝时转为“待核查”，保留全部验证码和已用额度。

管理员应先查看 [SMSBower 激活历史](https://smsbower.app/cabinet/client/phonehistory) 及相应邮箱订单、扣款记录，再核对“待核查”或“接码状态待确认”的订单。确认资源未收码且已释放时可选“已释放”；确认已消耗时可选“已消耗”，该资源最多计 1 个成功额度。已有验证码记录的订单不能选“已释放”。不能仅凭本地倒计时或“查无订单”认定退款；本系统的额度处理不代表向用户退还现金。

## 升级已有数据

邮箱等待时间由原默认 20 分钟一次性迁移为 25 分钟，包括设置、邮箱 CDK 快照及尚未分配的排队请求；已改为其他时长的配置保持不变。已分配订单保留固定截止时间，避免超过可能来自上游的更早期限；排队截止时间也不延长。迁移后再次主动设置 20 分钟不会在下次启动时被覆盖。

首次运行新版时，原 `max_attempts` 会迁移为 CDK 的成功额度 `usage_limit`，已有收码或已确认消耗的订单每单计 1 次。迁移和历史验证码补齐在同一事务中完成，仅执行一次，重启不会再次扣额度。原购买尝试数保留为历史信息，不再用于限制取消重取。

旧版本只保存了 CDK 哈希，无法从哈希恢复完整码。管理员可在列表“补录”中提交之前复制或导出的原始 CDK；后端核对其哈希后加密保存。持有旧 CDK 的用户正常兑换时，也会自动补存其完整码。尚未补录或兑换的旧码仍显示脱敏值和“待补录”，原兑换能力不受影响。新生成的 CDK 均可直接回看完整内容。

## 部署与备份

### 程序更新

后台“设置 → 程序更新”支持手动检查、立即更新，以及自动检查和自动更新开关。自动检查每 6 小时执行，安装脚本首次部署默认开启自动更新。活动订单结束后才会安装，安装期间暂停新的资源领取；只下载固定 GitHub 仓库的正式 Release，校验 SHA-256 后替换程序，保留旧程序 `.previous` 与原配置、数据。

Linux 安装服务由 systemd 重启；Windows 正式版本通过后台辅助进程替换并重启。辅助进程仅对启动失败尝试退回旧程序，不提供 HTTP 健康检查失败后的自动回滚。普通源码构建的 `dev` 版本只检查、不自动安装；当前 Docker 构建同样只检查，应重新构建或更新镜像。安装、权限、备份与回退步骤见 [安装与更新说明](docs/INSTALL.md)。

### Windows / Linux 程序

```powershell
go test ./...
go vet ./...
go build -trimpath -ldflags="-s -w" -o bin/atelier.exe .
```

Linux 上将构建输出改为 `bin/atelier` 即可。运行文件已包含页面资源；部署时保留可执行文件、对应配置及持久化数据目录。运行账户需要写入 `DATA_DIR` 的权限。

默认监听 `0.0.0.0:8080`，可通过 `http://服务器IP:8080` 访问。使用 HTTPS 反向代理时可自行改为仅代理可访问的监听地址，将 `COOKIE_SECURE=true`，并保留原始 `Host` 请求头。`TRUSTED_PROXIES` 可填逗号分隔的真实代理 CIDR，用于从 `X-Forwarded-For` 识别客户端 IP；直连时保持为空。程序本身提供 HTTP，不负责申请 TLS 证书。

管理员会话使用 HttpOnly、SameSite=Strict Cookie；订单访问令牌保存在浏览器当前标签页的 `sessionStorage` 中。程序重启后需要重新登录后台。CDK 和订单令牌均应像凭据一样妥善保管。

每个数据目录只允许一个进程使用；启动锁会拒绝第二个实例。本版本按单实例设计，不应将同一数据库用于多副本部署。

备份前先停止程序，再复制整个 `DATA_DIR`，包括 `atelier.db`、可能存在的 SQLite 附属文件和 `secret.key`；管理员密码哈希、加密的 API 密钥及加密的完整 CDK 均包含在数据库中。旧版本留下的 `admin.json` 可一并保留。不要只备份数据库或单独重建 `secret.key`，否则已保存的 API 密钥和完整 CDK 无法解密。恢复时将完整目录放回，并使用原来的模式和配置启动。

### Docker

项目提供 `Dockerfile` 和 `compose.yaml`。先准备 `.env`，然后启动演示实例：

```powershell
docker compose -p atelier-demo up -d --build
docker compose -p atelier-demo logs -f
```

真实模式使用已改为 `APP_MODE=live` 的配置，并使用独立项目名，避免与演示实例共享数据卷：

```powershell
docker compose -p atelier-live up -d --build
```

切换前停止使用相同主机端口的旧实例。Compose 将端口绑定到主机 `0.0.0.0:8080`，并将容器数据目录固定为 `/data`，保存在项目对应的命名卷中；它会覆盖 `.env` 的 `LISTEN_ADDR` 和 `DATA_DIR`。备份应停止容器后复制完整数据卷。`docker compose down` 保留数据卷，追加 `-v` 会删除数据。

## 接口与验证范围

用户接口包括 `/api/config`、`/api/inventory`、`/api/redeem`、`/api/orders/current`、`/api/orders/cancel`、`/api/orders/next-code`、`/api/orders/complete`、`/api/orders/replace`；用户订单接口使用 Bearer 令牌。后台位于 `/api/admin/*`，使用管理员 Cookie。健康检查为 `GET /healthz`。请求体为 JSON，接口约定见 [CONTRACT.md](CONTRACT.md)。

后台“接码”页可直接领取手机号或邮箱，无需生成或输入 CDK，也不消耗 CDK 额度。国家、域名和价格上限沿用“设置”，管理员不受用户兑换开关限制。每类同时保留一个未结束资源，完成或取消后可继续领取；邮箱支持最多三封接码。刷新、请求重试和重启不会自动重复购买。管理员资源仅能在登录后台后操作。

邮箱领取遇到明确缺货时会自动排队，每 5 秒尝试一次，默认等待 10 分钟。用户和管理员可在领取前设置 1–1440 分钟，并在排队中修改；时长始终从该次领取请求开始计算，缩短至已过去的时间会结束排队，不会因反复保存而重新计时。两端都可查看倒计时、取消排队；排队保存在服务端，关闭页面仍继续，重启后恢复未到期的队列。排队沿用最初的服务、域名、价格上限，不自动加价；邮箱真正分配后才开始计算本地接码等待时间，首次收到验证码才扣一次 CDK 额度。排队超时或取消不扣额度，之后可重新领取。余额不足、限价拒绝等其他明确错误结束排队；网络超时或结果不明转待核查，防止重复购买。更新前已有的失败订单不会自动加入队列，已有排队订单保留原截止时间。

用户端与后台顶部显示“邮箱参考余量”，按当前服务、域名及价格上限查询上游，每 30 秒刷新。库存报价有数量不保证当前能分配；同条件下最近两分钟明确分配无货时，保留参考数量并标注“暂不可分配”，报价刷新不会立即清除此状态，成功分配后清除。观察状态保存在内存中，重启或过期后恢复未确认。无法读取或尚未配置时显示“—”，查询得到零库存或报价超过限价时显示“0”。演示实例显示固定模拟库存 128，不代表真实余量。

本地测试覆盖并发兑换、成功额度、同邮箱多封接码、订单生命周期、凭据保护及上游响应解析。自动化测试使用本地模拟上游，不发起付费购买；真实库存、价格、验证码送达、扣款和退款需使用实际账号验收。

上游接入细节见 [docs/PROVIDER.md](docs/PROVIDER.md)。官方资料：[手机号 API](https://smsbower.app/api/?page=client)、[邮箱 API](https://smsbower.app/api/?page=mails)、[国家与服务表](https://smsbower.app/api/?page=other)。

界面统一使用本地打包的站酷快乐体，字体许可随资源提供，页面无需请求外部字体服务。猫咪品牌形象由内置生图工具生成，站点标识、首页插画及网页收藏图标均使用此形象。按钮采用单层平面样式；减少动态效果偏好会关闭循环装饰与位移动画。
