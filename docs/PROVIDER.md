# SMSBower 接入说明

核验日期：2026-10-07。实现位于 `internal/provider`，不依赖浏览器登录、Cookie 或历史页面抓取。

## 已核验的接口

官方 API 主机为 `https://smsbower.page`。手机号与邮箱的 OpenAI (ChatGPT) 服务编码分别在各自服务表中核验，均为 `dr`；并非根据其中一种资源推断另一种。

| 资源 | 获取 | 查询验证码 | 取消 | 完成 | 下一封 |
| --- | --- | --- | --- | --- | --- |
| 手机号 | `/stubs/handler_api.php?action=getNumberV2` | 同路径，`action=getStatus` | 同路径，`action=setStatus&status=8` | 同路径，`action=setStatus&status=6` | 不提供 |
| 邮箱 | `/api/mail/getActivation` | `/api/mail/getCode`，参数 `mailId` | `/api/mail/setStatus`，参数 `id`、`status=2` | 同路径，`status=3` | 同路径，`status=5` |

两种分配请求都发送管理员设置的 `service` 和 `maxPrice`（大写 `P`）。手机号发送明确的 `country` 数字编码；邮箱发送明确的 `domain`，默认建议 `gmail.com`，并显式发送 `alias=0` 关闭别名模式。不会自动换国家、换域名、换服务、切换别名或提高价格。邮箱明确缺货时由应用层队列按原参数重试；已分配或结果不明的购买不会重放。按[官方美元转换公告](https://smsbower.app/cn/blog/transition-to-usd)，价格查询和 `maxPrice` 均使用 USD；本程序不进行货币换算，也不把网页展示价格当作保证成交价。

邮箱分配的明确拒绝包括 `No mails yet`（当前条件下无可分配资源）、`Insufficient balance`（余额不足），以及[官方链接的 Postman 文档](https://documenter.getpostman.com/view/16514200/2sAXxLCEma)列出的 `Not available at this price. Try another`（当前价格上限下无法分配）。限价拒绝仅在完整 JSON 的 `status=0` 且没有邮箱地址或 `mailId` 时返回 `price_unavailable`、`Uncertain=false`。响应附带的 `data.actual_available_price` 等原始信息不会向客户端透出，也不用于自动提高价格。带已分配邮箱/ID、缺失状态、纯文本或损坏响应仍需按不确定结果核验。不能仅凭 `No mails yet` 推断为价格问题。

手机号错误 `EARLY_CANCEL_DENIED` 表示购买后至少等待 2 分钟。本地从收到分配结果起计算 2 分钟，以免网络延迟缩短保护时间。用户可立即提交取消请求，提前提交时先持久保存 `cancel_pending`，后台继续查询并在允许释放后自动取消。收到拒绝时按返回的重试间隔处理；确认释放前不允许重新分配。邮箱文档未给统一最短取消时间；如果平台拒绝取消，本地必须继续保留订单。

邮箱完成状态 `3` 会关闭激活，并从预留余额扣款。手机号 `STATUS_WAIT_RETRY:上次验证码` 仍包含已收到的代码，因此按已收到处理，不会因此重新释放 CDK。

邮箱状态切换按操作校验成功文案。[官方链接的 Postman](https://documenter.getpostman.com/view/16514200/2sAXxLCEma) 区分 `status=3` 的 `Activation succeed`、`status=5` 的 `Wait for next code` 和 `status=2` 的 `Success`。主页面的通用 `Success` 示例仍兼容。只有外层 `status=1`、文案符合当前操作、且没有非空错误字段时才接受；其它操作的成功文案、矛盾错误、未知或不完整响应不能作为当前操作成功的证据。此前仅识别 `Success` 会误判实际已完成的订单和已进入下一封的邮箱。

同一 Postman 提供只读 `/api/mail/getStatus?api_key=...&id=...`。可选 `CompletionStatusClient` 用于核验完成结果，不重放购买或状态切换：要求外层 `status=1`，并从 `data.status` 读取实际状态。目前只将有正式示例的 `3` 视为 `completed`；其他合法整数均为未确认终态的 `waiting`，不依据 `setStatus` 请求参数推断查询响应的其他终态编号。缺少激活、缺字段、损坏响应或查询失败都不能证明完成。`status_description`、`last_code` 不参与完成判断，也不会从该接口回传；`getCode` 再次返回旧验证码同样不能证明已经关闭。2026-10-07 已对一条本地完成待确认的真实订单只读核验 `getStatus`，确认上游状态 `3`；没有为该核验新增付费订单。

邮箱收到前两封验证码后，后台自动通过可选 `NextCodeClient` 接口将同一 `id` 设置为状态 `5`，继续查询下一封邮件，无需用户点击，关闭页面仍会执行；不会为此重新调用购买接口。本程序按业务要求最多保留同一邮箱的 3 轮验证码。当前公开邮件 API 明确支持等待下个验证码，但没有公开承诺每种邮箱、每个服务一定能收到 3 封；次数上限是本程序的业务限制，仍受上游可用状态和期限约束。CDK 的成功额度按已收到有效验证码的邮箱计数，同一邮箱的第二、第三封不再扣除新邮箱额度。

每次下一封请求先持久保存 `next_pending`，只有完整的成功响应才确认切换。明确拒绝会保留已收验证码及当前轮次，每轮最多自动尝试 3 次、间隔 30 秒；预算持久保存在 `order_auto_mail`，重启不重置。超过自动尝试次数后页面显示“重试接收”，仍可通过原手动接口继续尝试。超时、非成功 HTTP 状态、重定向、未知或损坏响应返回 `Error.Uncertain=true`，应用保留待核验状态，仅查询、不重放 `status=5`；中断后遗留的 `next_pending` 同样如此。未观察到新的等待状态时，紧邻上一封的相同验证码不会被当作新邮件；观察到等待后，允许下一封验证码文本相同，并持久保存该等待证据。上游只提供验证码文本、不提供邮件唯一标识，因此对连续直接返回的同码采取保守处理。

依据：[手机号 API](https://smsbower.app/api/?page=client)、[手机号服务表的官方法语页面](https://smsbower.app/fr/api)、[邮箱 API 与服务表](https://smsbower.app/api/?page=mails)、[邮箱服务表的官方西语页面](https://smsbower.app/es/api?page=mails)。

## 邮箱剩余量

通过可选 `InventoryClient.EmailInventory` 只读查询官方 `/api/mail/getPriceRests`，仅发送 `api_key`、`service`、`domain`。按[邮箱 API 文档](https://smsbower.app/api/?page=mails) 的 `data[service][domain]` 读取 `price` 与 `count`，不合并其他服务或域名，也不调用购买接口。库存接口没有公开的 `alias` 或 `maxPrice` 参数，因此此数字是该服务、域名的上游参考库存，不代表当前账户按所设条件一定可以购买的数量；也不承诺是经单独核验的非别名专属库存。购买仍沿用 `alias=0`。官方未说明省略 `alias` 时的默认值，不据此假设或自动切换购买模式。

本程序使用精确十进制数比较报价与已设置的价格上限：超出上限显示可用量 0；缺少价格配置时返回未配置。只有有效的库存结果或平台明确 `No mails yet` 等售罄回复可产生确定的 0。格式异常、目标服务/域名缺失、鉴权失败、网络错误都表示剩余量未知，不伪装为售罄。整数库存限制在 0 至 2,147,483,647，拒绝负数、小数、溢出及非法数据。接口沿用响应长度限制、禁止重定向及密钥脱敏保护。库存会随上游销售变化，仅代表查询时刻，不保证随后的分配成功。

演示模式固定显示 128 个模拟邮箱，进程重启后不变，不查询或购买真实资源。该查询及异常分支已使用本地模拟服务器验证，也已使用已配置的 API 密钥只读核验真实库存接口；未为验证库存功能发起真实付费订单。

## 临时资源与截止时间

邮箱默认 25 分钟，手机号默认 20 分钟，都是分配成功后本程序的本地等待上限，不构成上游永久使用或确定有效期的承诺。SMSBower [官方说明](https://smsbower.app/es/blog/virtual-sim-guide-temporary-numbers) 描述了手机号约 20 分钟的使用窗口；邮箱的[官方详细文档](https://documenter.getpostman.com/view/16514200/2sAXxLCEma#3f77467c-5969-4b48-8f97-53395f094fdd)描述了 3 分钟接码窗口，但未说明续收是否重置时间；当前单次 getActivation/getStatus 文档及已核验的真实 getStatus 回包都没有每笔准确到期字段。本地时长设置不能当作官网有效期，自动续收也不重置本地截止时间。

首次升级会将原默认 20 分钟的邮箱设置、邮箱 CDK 快照及未分配队列请求一次性改为 25 分钟，保留其他自定义时长。已分配订单无法区分原截止时间是否由上游更早到期字段限定，因此保留原截止时间，不盲目延长；排队截止时间保持不变。

分配返回里若出现明确到期字段 `expiresAt`、`expires_at`、`expirationTime`、`expiration_time` 或 `activationEndTime`，支持 RFC3339、Unix 秒与毫秒，并取它与本地等待上限中较早的时间。这些字段属于可选兼容，不是文档承诺存在的字段。`activationTime` 不当作到期时间。倒计时结束只触发查询及取消流程；只有平台确认取消或明确释放，CDK 才能重新分配。

查不到激活、响应损坏、网络超时、未知状态及取消失败，都不能证明资源已退款。分配请求一旦出现网络错误、非 2xx 状态或不完整响应，可能已产生实际订单：返回 `Error.Uncertain=true`，需要管理员在上游历史记录核验后处理，不自动重试。邮箱完整响应中的明确 `no_stock` 触发应用层排队，间隔 5 秒、默认 10 分钟，用户可设置 1–1440 分钟并在排队中调整。手机号的明确缺货仅在同一渠道、相同购买参数下尝试最多 10 秒，仍缺货则隐藏该渠道 10 分钟；余额不足、密钥错误、限价拒绝和结果不明均不触发这种重试。队列不是上游提供的预约或位置接口，不承诺优先级、排位或最终有货。

演示模式在订单 ID 内编码时间及类型，重启后仍能继续原订单。第一轮约 15 秒出现演示验证码，取消等待 10 秒；号码使用虚构示例号段，邮箱使用 `example.invalid`，不会产生真实费用。邮箱第二、第三轮分别在分配后约 30、45 秒可用，由应用持久化轮次并调用可选 `RoundPollClient` 接口，因此进程重启不会丢失或重置轮次；每轮使用不同的演示验证码。演示的完成、取消终态由应用数据库持久化。

## 配置与上线核验

- 在管理员设置页保存 API 密钥，加密存入数据库并立即生效；接口只返回配置状态，不回传密钥。环境变量只保留首次迁移兼容。日志、错误消息不会透出请求 URL、原始响应或传输错误。
- API 地址必须是无路径、无查询串的 HTTPS 根地址；仅本机回环地址允许 HTTP。拒绝重定向，防止密钥随查询参数转发到其他站点。
- 国家与价格上限需要管理员按实际供应配置；不设猜测值。邮箱域名需在上游实际可用。
- 只支持临时接码，不提供邮箱密码、完整收件箱或长期号码租用。
- 库存查询成功不能代替分配成功。实际使用前应以少量真实订单核验手机号与邮箱全流程，包括未收码取消、收码完成及过期后核验；实际扣款、退款和送达情况以供应商记录为准。

接口格式与异常处理由本地 `httptest` 模拟服务器验证，不能替代真实账号的低量验收。
