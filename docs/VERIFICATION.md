# 验证说明

## 自动化测试

运行 `go test ./...` 与 `go vet ./...`，覆盖管理员初始化、鉴权、CDK 加密保存与并发兑换、订单额度、排队、取消、续收及重启恢复。上游接口测试使用本地模拟服务，不购买真实资源。

邮箱测试覆盖 25 分钟默认等待、旧配置迁移、每个有效邮箱仅扣一次额度、三封邮件自动续收、重复验证码去重、请求结果不明时不重放，以及明确失败后的有限重试。

手机号测试覆盖旧 CDK 跟随后台国家及价格限制、设置与购买并发、同渠道 10 秒有限重试、10 分钟隐藏及重启恢复、超时不重购、立即提交取消和取消期间收到验证码的处理。浏览器测试覆盖复制手机号去除 `+`、取消确认期间禁止重新购买、获取中防止重复提交，以及自动刷新渠道并清除失效选择。

渠道测试覆盖价格降序和同价稳定排序、价格上限、准确匹配国家及渠道评级、接口未提供评级与请求失败的区别，以及国家与评级查询独立超时。只读查询失败不会伪装成已确认的“未评级”。

余额测试覆盖管理员权限、十进制精度、真实零余额与查询失败的区别、短时缓存及并发查询、密钥切换隔离，以及后台页眉刷新、退出登录清除和移动端布局。该显示读取供应商余额，不推算退款，也不会将金额持久保存在浏览器中。

更新测试覆盖版本比较、正式 Release 选择、下载来源与 SHA-256 校验、归档路径保护、旧程序保留、重启辅助进程、管理员接口权限和活动订单保护。模拟分段下载验证中途可读的真实字节进度、失败后的进度重置，以及实际大小和校验值不匹配时拒绝安装。Chromium 测试覆盖进度弹窗、自动安装、断线重连、会话失效后恢复版本核对及移动端布局。前端通过 JavaScript 语法检查，提示音、标签提醒和更新交互另有 Node.js 测试。

## GitHub Actions

推送正式版本 tag 后，工作流依次执行测试、五个平台的编译和 Linux 安装烟测，全部成功后才发布 Release。

安装烟测在独立的 Ubuntu Runner 中运行真实安装脚本及 systemd：检查非 root 服务运行、管理员初始化、配置与 CDK 保存、错误校验值被拒绝，再执行升级，核对数据库、密钥、配置和备份。下载源由严格匹配的本地测试包替代，不访问真实短信或邮件服务。

具体执行结果见仓库的 [Actions](https://github.com/MengStar-L/OpenAIMailTransaction/actions)。

## 验证范围

自动化测试不代表真实供应商始终有库存，也不保证上游退款、续收或有效期。上游分配结果、实际费用和退款以供应商记录为准；库存仅为参考。

应用自动更新保留数据和上一版程序。独立进程更新辅助程序可在新版无法启动时恢复旧程序；不承诺根据 HTTP 健康状态自动回滚。Linux 安装脚本会检查健康状态并保留升级前备份，异常时需按安装文档检查日志或恢复。

Docker 构建及远程公网部署不属于 Release 工作流的安装验证范围。
